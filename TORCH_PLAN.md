# Day 3 PyTorch Migration Plan

- **Scope** Convert `sessions/K_FFN.ipynb`, `sessions/K_CNN.ipynb`, `sessions/CNN_timeseries.ipynb`, `sessions/audio.ipynb`, and `sessions/pretrained.ipynb` (plus matching solutions) from Keras to PyTorch; exclude exercises and Days 1, 2, 4; keep datasets, examples, and narrative flow.
- **Notebook style** Preserve logo/title cells and “In this session we will…” intros; maintain markdown narratives and plot order; add short PyTorch primers before first use (tensors/autograd → `nn.Module`/optimizer → datasets/dataloaders → GPU handling).
- **Shared setup** Replace `jax`/`keras` imports with `torch`, `torch.nn as nn`, `torch.nn.functional as F`, `from torch.utils.data import DataLoader, TensorDataset`; set `device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')`; move tensors/models to device; keep `%matplotlib inline`, reproducible seeds (`torch.manual_seed`).
- **K_FFN.ipynb** Introduce PyTorch basics; build an `nn.Module` FFN; load MNIST/Fashion-MNIST via `torchvision.datasets`; define loss (`nn.CrossEntropyLoss`) and optimizer (`torch.optim.SGD` or `Adam`); write explicit train/eval loops with progress prints; show `torch.save`/`torch.load`; mirror existing loss/accuracy plots.
- **K_CNN.ipynb** Rebuild CNN with `nn.Conv2d`/`nn.MaxPool2d`/`nn.ReLU`/`nn.Linear`; keep architecture depth and dataset; reuse training loop helper from FFN; include parameter count and receptive field notes similar to current text.
- **CNN_timeseries.ipynb** Use FordA dataset with `TensorDataset` and `DataLoader`; switch to 1D convolutions (`nn.Conv1d`, `nn.MaxPool1d`); ensure channel-first reshaping; retain evaluation and plots.
- **audio.ipynb** Prefer `torchaudio` for loading/processing; use `torchaudio.transforms.MelSpectrogram`; build 2D CNN over spectrograms; handle batching/padding; reuse train/eval utilities; keep ESC-50 workflow and visualizations.
- **pretrained.ipynb** Replace Keras Applications with `torchvision.models` (e.g., `resnet50`, `mobilenet_v2`); show inference with `torchvision.transforms` and `torch.no_grad()`; add transfer-learning demo using frozen backbone + new head; show saving/loading `state_dict`.
- **Utilities & reuse** Keep helpers (`train_one_epoch`, `evaluate`, `plot_curves`) inside notebooks; first use should introduce/explain the helper, later notebooks can place the same helper at the top without re-explaining; keep loops explicit for teaching value.
- **Device selection** At the top of notebooks, set `device` with priority: CUDA GPU if available, else MPS (`torch.backends.mps.is_available()`), else CPU; move models/tensors accordingly.
- **Validation** Run each notebook end-to-end on CPU to check parity; note optional GPU/MPS acceleration; update `environment.yml` only if needed for `torch`/`torchvision`/`torchaudio` (CPU builds unless CUDA available).
- **Teaching notes** Emphasize PyTorch idioms: manual loops vs. `model.fit`, autograd, `.train()`/`.eval()`, `with torch.no_grad()`, device moves, and saving/loading; reference prior Keras/JAX experience to orient students.
